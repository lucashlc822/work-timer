# M2 — The sky

## Context

M1 shipped a correct timer on a plain background. M2 makes it rewarding: every
completed session becomes a star, stars build constellations the user chooses,
and the main screen becomes a night sky. The architecture doc only had a
one-line row for M2, so this plan is its full design. Execution step 1 commits
this plan as `docs/plans/2026-10-06-m2-sky.md`, as was done for M1.

### Settled before this plan (do not re-open)

| Question | Decision |
|---|---|
| Star identity | A star is its session's `seed`. Everything visual derives from it. |
| Renderers | Canvas 2D for the ambient starfield, SVG for earned stars and constellations. |
| Motion | `prefers-reduced-motion` stops twinkle and drift; the loop pauses when hidden (desktop visibility works since PR #8). |
| Cancelled sessions | Earn no star (the cancel dialog already says so). |

### Decided with Lucas on 2026-10-06

| Question | Decision |
|---|---|
| Where the sky lives | Behind the timer on the main screen. A "View sky" button fades the timer controls so the stars can be hovered. No new route. |
| Who chooses | The user picks the next constellation from a catalogue. |
| Shapes | **Both**: a hand-designed catalogue *and* generated "wild" constellations, offered side by side. |
| Difficulty | A combination of star count, session length and total focus time (see *Tiers*). |
| Gating | Simple gate now: medium unlocks after one finished easy, hard after one finished medium. M6 later folds this into its unlock system. |

### Decided in this plan (reopen in review if you disagree)

| Question | Decision | Why |
|---|---|---|
| How the three difficulty levers combine | **Star count** and a **minimum session length per star** are the gates. **Total focus time** is not a third gate (it follows from the other two) but is shown in the picker ("about 4 h of focus") and makes longer sessions' stars **brighter and larger**. | Three independent gates would mostly duplicate each other: N stars of 50+ min already guarantees N×50 min total. Making length visible in the art rewards deep work without a confusing second progress bar. |
| A completed session too short for the current constellation | Becomes a **wandering star**: shown in the sky, counted in stats, not placed in the constellation. The idle screen warns *before* start ("won't count toward The Heron: needs 50+ min"). | Never silently waste a session; the warning keeps it from being a surprise. |
| Sessions from before M2, or with nothing chosen | Wandering stars. | Existing history shows up immediately. |
| Switching mid-constellation | Allowed, behind a confirmation. The abandoned one stays in the sky, dimmed and unfinished. | Being stuck on a hard constellation would be worse. |
| Sky size | Fit-all view, no pan or zoom. | Enough for months of use; pan/zoom is a later concern. |

## The core idea: the sky is derived, not stored

The only new thing persisted is **the user's choice**: "at time T I started
building constellation C". Which stars belong to which constellation, whether it
is complete, when it completed, and what is unlocked are all **derived by a pure
function** over sessions and choices:

```ts
// src/features/sky/domain/derive.ts
export const deriveSky = (sessions: CompletedSession[], choices: ConstellationChoice[]): SkyState;
```

- A choice's **window** runs from its `chosenAt` until the next choice's `chosenAt`.
- Completed sessions are taken in `endedAt` order. A session whose `endedAt` falls in a window, and meets that tier's minimum length, fills the next slot.
- Once all N slots are filled, the constellation is **complete**, and its `completedAt` is the Nth star's `endedAt`. Later sessions in the same window become wandering until a new choice.
- Unlocks are counts over completed constellations by tier.

This matches the project's existing rules (completed sessions immutable, streaks
derived by query). Finishing a session writes nothing new. Choices are
append-only, so M5 sync stays conflict-free.

## Tiers

```ts
// src/features/sky/domain/tiers.ts
export const TIERS = {
  easy:   { stars: [4, 5],   minSessionMin: 0,  style: 'plain' },
  medium: { stars: [7, 9],   minSessionMin: 25, style: 'glow' },
  hard:   { stars: [12, 16], minSessionMin: 50, style: 'nebula' },
} as const;
```

- **Plain:** stars and thin lines.
- **Glow:** blurred line glow and a soft halo per star.
- **Nebula:** a seeded pastel nebula behind the shape, shimmering lines, bloom on stars, and a decorative name label.

**Dev builds only** (`import.meta.env.DEV`): the minimums become medium 1 min and hard 2 min, and a 2-min dev preset joins the existing 1-min one. Medium and hard can then be tested in minutes, and a 1-min session aimed at hard tests the wandering path.

**Feature boundary:** the timer never imports sky. `app/` composes them, passing
sky components into the timer's render props. Sky reads sessions straight from
`shared/db` (`SessionRow`), not through the timer.

### Contracts and edge cases

```ts
interface ConstellationRow {           // shared/db/schema.ts, append-only
  id: string; source: 'catalogue' | 'generated';
  shapeId: string | null;              // catalogue key, when source = catalogue
  seed: string | null;                 // generator seed, when source = generated
  tier: 'easy' | 'medium' | 'hard';
  chosenAt: number; clientCreatedAt: number; syncedAt: number | null;
}
```

- **Generated options are stable until picked.** Option i of tier t is seeded from `hash(localUserId, t, choiceCount, i, rerollCount)`. Reload shows the same three; a "Shuffle" button increments an in-memory reroll counter.
- **The generator always returns a usable shape.** Poisson-disk points (minimum spacing), a Euclidean minimum spanning tree for lines, plus 1–2 short loop edges for hard tier. Shapes with crossing edges or a bounding box below 40% of the unit square are rejected and redrawn from the next RNG values, with a hard cap of 50 tries before a safe fallback layout.
- **Star look:** colour interpolates `--color-star-cool`, `--color-star-core` and `--color-star-warm` along a seeded temperature. Brightness and radius scale with `actualFocusS`, clamped from 5 min to 3 h.
- **SVG colours come from tokens via CSS variables.** Per the CLAUDE.md environment note, gradient stops fail silently to black if a variable doesn't resolve, so verify computed values.
- **Choosing while a session runs is allowed.** Membership uses `endedAt`, so that session counts toward the new choice.
- **A schema v2 migration only adds a table.** v1 rows are untouched.

2. Unit: `deriveSky` gives the same output for the same sessions and choices regardless of input order.
3. Desktop: note star positions, reload with F5 (confirm `'reload'` with the navigation snippet), and quit and relaunch. *Pass:* every star and constellation is in the same place with the same colour.

**O2 — A completed session becomes a star, exactly once.**
4. Choose an easy constellation and complete a 1-min dev session. *Pass:* the result screen shows the star and "Added to <name>: 1 of N", and the star appears in its slot behind the timer.
5. Cancel a session. *Pass:* no star, nothing added.
6. Unit: completing the Nth star marks the constellation complete, with `completedAt` equal to that star's `endedAt`; the next session becomes wandering.

9. Unit: a choice made mid-session counts that session (`endedAt` membership).

**O4 — The catalogue offers hand-designed and generated constellations.**

11. Reload. *Pass:* the same generated options appear. Shuffle. *Pass:* new ones.
12. Switch constellations mid-way and confirm. *Pass:* the old one stays in the sky, dimmed and unfinished; new stars go to the new one.

**O5 — Gating.**

**O6 — Harder tiers look richer.**

**O7 — It is cheap to leave running.**

## Known limits

- **No pan or zoom.** A very large sky gets crowded in fit-all view.
- **Sync may later insert past sessions** (M5) and shift a past constellation's slots. That's acceptable, because derivation is deterministic on any one device.
- **Generated shapes are only as good as their constraints.** That's why they sit next to the hand-designed ones rather than replacing them.

## Model recommendation

**Switch to the faster model (Sonnet) for execution.** This is new feature
building against a settled architecture, with no multi-file refactoring of
existing code and no tricky debugging expected. The correctness-sensitive parts
(`deriveSky`, the generator, the v2 migration) are fully specified above and
guarded by unit tests written first. Visual tuning is iterative, and screenshots
drive it rather than deep reasoning.
