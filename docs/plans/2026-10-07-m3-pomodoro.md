# M3 — Pomodoro

## Context

M1 shipped a correct countdown timer and M2 turned completed sessions into stars
and constellations. M3 adds the second session mode the architecture promised:
Pomodoro, meaning focus blocks separated by short breaks, with a long break after
every Nth block. The architecture doc's M3 row says "Phase machine, break-exempt
abandonment semantics". Half of that is already moot, because abandonment was
removed on 2026-08-31 (leaving never forfeits anything). This plan is the full
design. Execution step 1 commits it as `docs/plans/2026-10-07-m3-pomodoro.md`,
as was done for M1 and M2.

### Decided with Lucas on 2026-10-07

| Question | Decision |
|---|---|
| What earns a star | **One star per completed focus block.** Each block is an ordinary session row and becomes its own star. |
| When a break ends | **Wait for a click.** Focus → break is automatic. Break → next focus needs the user to press Start. Nothing can mint a star while the user is away. |
| Configurability | **Fully custom**: focus length, short break, long break, and blocks per long break. The settings are saved. |

### Decided in this plan (reopen in review if you disagree)

| Question | Decision | Why |
|---|---|---|
| How a run is stored | **No `session_phases` table** (this supersedes the architecture doc's data model). A focus block is a `SessionRow` with `mode: 'pomodoro'` plus two new optional fields: `runId` and `runIndex`. Breaks are **not persisted as history**. The only stored state for a break is the in-flight run pointer in `meta`, which is deleted when the run ends. | Blocks stay immutable and append-only, so M5 sync is unchanged, and the sky needs **zero changes** (it already reads every completed session). A break has no outcome worth keeping. |
| Optional fields vs a Dexie version bump | `runId?: string`, `runIndex?: number`. Unindexed, so there is **no `db.version(3)`**. Absent means "not part of a run". | Rows written before M3 never get rewritten, so completed sessions stay immutable. An index can come with M4 if stats need it. |
| Ending early during a focus block | Cancels **that block only** (no star) and ends the run. Stars from earlier blocks stay. | Matches the existing cancel. Losing several blocks' worth of work to one click would be punitive. |
| Ending the run during a break, or once a break is over | "End run" clears the run and shows a run summary (blocks done, total focus). It writes no session. | Nothing is in flight, so there is nothing to cancel. |
| Skip break | Offered during a break. Jumps straight to "break over" (it still waits for the Start click). | The common need. Starting the next block is still one deliberate click. |
| Settings mid-run | The settings panel is disabled while a run exists. The run stores a **snapshot** of its settings when it starts. | Avoids defining what "change break length during the break" would mean. |
| Mode memory | The Countdown/Pomodoro toggle and the Pomodoro settings are kept in `meta`. | Same place as other local singletons. M5 can move them to `profiles.settings`. |
| Tray during a break | Tooltip reads `Break · N min left`. This needs one optional `label` argument on the completion port. | "N min left" alone would look like focus time. |
| Away time | Only measured during focus blocks (unchanged). Breaks are never counted as away. | Being away during a break is the point of a break. |

## How a run behaves, end to end

1. Idle, Pomodoro selected → **Start** creates run `R` in meta (settings snapshot, `blocksDone: 0`, no break) and starts block 1 as a session (`mode: 'pomodoro'`, `runId: R`, `runIndex: 1`, `plannedDurationS = focusMin*60`).
2. Block completes (timestamp-decided, exactly like countdown) → the session is finished as `completed` with `endedAt` = planned end. In the same transaction, run meta becomes `{ blocksDone: 1, break: { kind, startedAt: block.endedAt, durationS } }`. **The break starts at the block's planned end, not when it was noticed.**
3. During the break: a countdown with the new star, plus **Skip break** and **End run**. The host deadline is armed for the break end, with the notice "Break's over — ready for block 2".
4. Break over (`now >= break end`, derived) → "Break's over" screen with **Start block 2** and **End run**. Nothing starts by itself.
5. **Start block 2** clears `break` from run meta and starts the next session. Repeat. The long break comes after every `blocksPerLongBreak`-th block.
6. Run ends via **End early** in a block (that block is cancelled, then the summary) or **End run** between blocks (straight to the summary). Run meta is deleted.

Resume (reload, relaunch, waking from the tray) is always derived from what is stored:

| Stored state at load | Resumes to |
|---|---|
| Active session (countdown or block), not yet due | `running` |
| Active session that is a block, now past its end | Complete it → break, and if the break has also elapsed → `breakOver` |
| Active countdown session past its end | `completing` → `finished` (unchanged) |
| No active session, run with `break`, break not over | `onBreak` |
| No active session, run with `break`, break over | `breakOver` |
| No active session, run without `break` (crash between steps 5's two writes) | `breakOver` (ready for the next block) |

## Contracts

### Storage — `src/shared/db/schema.ts`, `meta.ts`

```ts
// SessionRow additions (unindexed, optional — absent on countdown and pre-M3 rows)
/** Pomodoro only: the run this focus block belongs to. */
runId?: string;
/** Pomodoro only: 1-based position of this block in its run. */
runIndex?: number;

export const META_KEYS = {
  ...,
  /** The Pomodoro run in flight, or absent. See `PomodoroRunRow`. */
  activeRun: 'activeRun',
  /** Last chosen mode on the idle screen. */
  timerMode: 'timerMode',
  /** Saved Pomodoro lengths. */
  pomodoroSettings: 'pomodoroSettings',
};

export interface PomodoroSettingsRow {
  focusS: number; shortBreakS: number; longBreakS: number; blocksPerLongBreak: number;
}
export interface PomodoroRunRow {
  id: string;
  startedAt: number;
  settings: PomodoroSettingsRow;   // snapshot
  blocksDone: number;              // completed blocks only
  break: { kind: 'short' | 'long'; startedAt: number; durationS: number } | null;
}
```

`Row` types live in `shared/db` (a storage contract), and the domain types in `features/timer/domain` build on them. This is the same split as `SessionRow` / `ActiveSession`.

### Pure domain — new `src/features/timer/domain/pomodoro.ts` (+ `pomodoro.test.ts`)

```ts
export const DEFAULT_POMODORO: PomodoroSettings;            // 25 / 5 / 15 / 4 (in seconds where applicable)
export const POMODORO_LIMITS;                               // focus 5–180 step 5 min; short 1–30 step 1; long 5–60 step 5; blocks 2–8
export const clampPomodoroSettings: (s: Partial<PomodoroSettings>) => PomodoroSettings; // non-finite → default, then clamp; never NaN
export const breakKindAfter: (blocksDone: number, s: PomodoroSettings) => 'short' | 'long'; // long iff blocksDone % blocksPerLongBreak === 0
export const breakFor: (blocksDone: number, s: PomodoroSettings, startedAt: number) => RunBreak;
export const breakEndsAt: (b: RunBreak) => number;
export const breakRemainingMs: (b: RunBreak, now: number) => number; // clamped ≥ 0; clock-backwards safe like session.ts
export const isBreakOver: (b: RunBreak, now: number) => boolean;
export type RunVerdict = { kind: 'onBreak'; remainingMs: number } | { kind: 'breakOver' };
export const runVerdict: (run: PomodoroRun, now: number) => RunVerdict; // break null → breakOver
```

In dev builds only, `POMODORO_LIMITS` lower focus and break minimums to 1 min (`import.meta.env.DEV` read in the UI, as `DurationPicker` already does), so the acceptance run takes minutes.

### Types — `src/features/timer/domain/types.ts`

- `ActiveSession` gains `mode: SessionMode`, `runId: string | null` and `runIndex: number | null`.
- `SessionDraft` becomes a union: `{ mode: 'countdown'; plannedDurationS; tagId }` | `{ mode: 'pomodoro'; settings: PomodoroSettings; tagId }`. A Pomodoro draft starts a new run.
- `PomodoroRun` and `RunBreak` are the domain mirrors of the meta rows.

### Repository — `src/features/timer/data/sessionRepository.ts` (+ new `runRepository.ts`)

All of these are transactional over `sessions` + `meta`, so the session row and both pointers never disagree after a crash.

- `startSession(db, draft, ctx)`: a countdown behaves exactly as today. A Pomodoro draft also creates the `activeRun` row and writes block 1 with `runId`/`runIndex: 1`. It rejects with `ActiveSessionExistsError` (and the new `ActiveRunExistsError`) when anything is in flight.
- `startNextBlock(db, runId, ctx): Promise<ActiveSession>`: requires the run to exist and have no active session. It sets `break: null` and adds the block with `runIndex = blocksDone + 1`.
- `finishSession(db, id, ending)`: unchanged for countdown. For a block, **in the same transaction**: on `completed`, increment `blocksDone` and set `break = breakFor(...)` starting at `ending.endedAt`; on `cancelled`, delete `activeRun`. Stays idempotent: a second finish of an already-finished row changes nothing, including the run.
- `skipBreak(db, runId, now)`: sets `break.durationS` so the break ends at `now`. This keeps "the break is over" derived, rather than adding a flag.
- `endRun(db, runId): Promise<RunSummary>`: deletes `activeRun` and returns `{ blocks, focusS }` computed from sessions with that `runId`.
- `loadActiveRun` / `peekActiveRun`: these mirror the existing pair. `loadActiveRun` cleans a dangling run that has neither a break nor an active session **only** if that run has zero blocks (a crash between creating the run and the first block). Otherwise it is left to resume as `breakOver`.
- `load/read/saveTimerPrefs(db)`: mode and settings, read through `clampPomodoroSettings` so a corrupt meta value can never produce a NaN-length block.

### Machine — `src/features/timer/domain/timerMachine.ts` (extend, don't fork)

There is one machine, so all sequencing stays in one place. New context field: `run: PomodoroRun | null`. New states and events:

```
idle ── START ──▶ starting ──▶ running ──TICK_DUE──▶ completing
completing ──(countdown)──▶ finished                          (unchanged)
completing ──(pomodoro, onDone with updated run)──▶ onBreak | breakOver
cancelling ──▶ finished   (a cancelled block's result shows "Run ended — N stars this run")
onBreak   ── TICK_DUE[breakOver] ──▶ breakOver
onBreak   ── SKIP_BREAK ──▶ skipping ──▶ breakOver
onBreak | breakOver ── END_RUN ──▶ endingRun ──▶ runSummary ── DISMISS ──▶ idle
breakOver ── START_NEXT ──▶ startingNext ──▶ running
idle ── RESUME { session?, run? } ──▶ per the resume table above
```

- Actors are new named `fromPromise` actors that default to reject, like today: `startNextBlock`, `skipBreak` and `endRun`. `finishSession`'s output becomes `PomodoroRun | null`, so the machine learns the new break without a second read.
- Actions are `armBreak` / `disarmBreak`, the break deadline counterparts of `armCompletion`. The host deadline id is `break:<runId>:<blocksDone>`, so a stale arm can never cancel the next one.
- Guards are `isPomodoro` and `breakOver` (`isBreakOver(context.run.break, clock.now())`).
- Transient `*ing` states exist only while a write is in flight. This is the M1 rule, so a double click can never fire twice.

### Host — `src/shared/runtime/types.ts`, `desktop.ts`, `web.ts`, `src-tauri/src/deadline.rs`

- `CompletionPort.arm` gains an optional `label?: string`. Desktop passes it to Rust, and the tooltip becomes `{label} · {n} min left` when it is present. Web ignores it.
- Rust: add `label: Option<String>` to the `arm` command and include it in the existing `format!`. There are no other Rust changes.

### Hook — `src/features/timer/hooks/useTimerSession.ts`

- The status union gains `'onBreak' | 'breakOver' | 'runSummary'`. The hook exposes `run`, `startNext()`, `skipBreak()`, `endRun()` and `summary`.
- The resume effect loads both the session and the run, then sends one `RESUME`.
- A deadline effect for the break, like the existing session one: a re-scheduled `setTimeout` to the break end sends `TICK_DUE`, and a visibility return also sends `TICK_DUE`.
- Away tracking is only active in `running`. It is unchanged, so breaks are never counted.
- `start(draft)` saves the chosen mode and settings via `saveTimerPrefs`.

### UI — `src/features/timer/ui/`

- **New `ModeToggle.tsx`**: a two-option radiogroup (Countdown / Pomodoro) above the picker, styled like `DurationPicker`'s `Pill`.
- **New `PomodoroSettings.tsx`**: four labelled sliders (Focus, Short break, Long break, Long break every N blocks), using `POMODORO_LIMITS` and `clampPomodoroSettings`, with a one-line summary such as "25 min focus · 5 min breaks · 15 min after every 4th". In dev, the 1-min minimums are labelled "(dev)".
- **`TimerScreen.tsx`**: the idle screen shows the toggle and then either `DurationPicker` or `PomodoroSettings`. The Start label is "Start 25 min" or "Start Pomodoro". `slots.startHint` gets the block length, so the sky's "won't count toward…" warning works per block for free. The running screen shows "Block 2 · Pomodoro" above the countdown when `runIndex` is set.
- **New `BreakScreen.tsx`**: covers `onBreak` and `breakOver`. During a break it shows the just-earned star (via `slots.resultStar`, same `ResultInfo` as today), "Short break" or "Long break", a countdown (reusing `CountdownDisplay`), and **Skip break** / **End run**. Once the break is over, it shows "Break's over" with **Start block N** / **End run**.
- **New `RunSummary.tsx`**: "N stars this run · H h M m of focus", with **Done**.
- **`SessionResult.tsx`**: when a cancelled block ended a run, a line under the result reads "Run ended — N stars kept".
- **`MiniCountdown.tsx`**: also live-queries `peekActiveRun`. During a break it shows the break countdown labelled "Break". Once the break is over it shows `--:--`.

### Copy for notices

- Block done: title `APP_NAME`, body "Focus block done — {n}-min break." (This replaces the session notice for blocks.)
- Break over: "Break's over — ready for block {n+1}."

## Model recommendation

This extends the timer state machine and its resume logic across a persisted run, in the same correctness class (timestamps, crash and reload edges, idempotent finishing) that M1 was built on with the stronger model. It also touches storage, domain, hook, UI and Rust. **Stay on the stronger-reasoning model (Opus) for steps 2–4.** The UI and docs (steps 6–7) are straightforward and could switch to a faster model (Sonnet) once the machine's tests are green.
