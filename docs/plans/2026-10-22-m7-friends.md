# M7 — Friends: design and phased plan

Agreed 2026-10-22. Phase 1's detailed contract is in its PR (`supabase/migrations/*_m7_friends.sql` and `supabase/tests/m7_friends.test.sql`). Each phase below gets its own detailed plan (contracts,
edge cases, acceptance tests) before it is built.

## Context

Starkeep is solo today: every server row is readable only by its owner
(`(select auth.uid()) = user_id` on every policy, pinned by the catalogue
guards in `supabase/tests/isolation.test.sql`), and there is no display name —
the only identity is the email. Lucas wants friends: see each other's sky and
stats, focus together live, and build constellations that depend on each other.
Hard constraint: **simple to use and understand**, on web and desktop alike, and
free tiers only.

Research (for flavour, not copied): Forest's *Plant Together* — friends grow a
tree together and if anyone gives up, everyone's tree dies; Duolingo's *Friends
Quests* — two friends share one goal and each one's own progress counts toward
it; Focusmate — scheduled co-working, the "body doubling" effect of knowing
someone else is working right now.

### Decisions taken with Lucas (2026-10-22)

| Question | Choice |
|---|---|
| Focusing together, someone cancels | **Everyone's session fails** (Forest-style) |
| Shared constellation stars | **Either friend's completed session, any time**, fills it |
| What a friend sees | **Sky + summary stats** (total focus, streak, stars this week, focusing now). No tag names, no session-by-session history |
| How friends connect | **Friend code** (e.g. `STAR-7K2Q`) + display name; request → accept |

**Decision to record in CLAUDE.md in phase 4** (it amends "Leaving the app
never forfeits a session"): *in a together session, any member's deliberate
cancel ends everyone's session as ended-early. Leaving, closing, sleeping or
going offline still never forfeits — only a deliberate cancel does, and now a
friend's counts too. A cancel that reaches a device after its session already
completed changes nothing: completed sessions stay immutable.*

## The feature, as a person sees it

One new footer pill, **Friends** (an overlay panel like Stats/Stardust):

1. **First open:** "Pick a name your friends will see" → display name. Your
   friend code is shown with a Copy button.
2. **Add a friend:** type their code → they see a request → Accept / Decline.
3. **Friend list:** name, a small star glyph, "Focusing now · 18 min left" or
   "Last focused yesterday", streak. Tap a friend → **their sky** (read-only, in
   their theme) with a summary strip: focus this week, stars this week, streak,
   constellations completed.
4. **Focus together:** from the timer, "Focus with friends" → pick friends and a
   length → they get an invite (in-app, plus a desktop notification) → a lobby
   shows who's in → the host presses Start → everyone's timer runs to the same
   end time. Ending early ends it for everyone ("Alex ended the session").
   All finish → everyone gets their star **plus a together bonus**.
5. **Shared constellation:** on a friend's page, "Start a shared constellation"
   → pick a shape (same picker as now) → your friend accepts → every session
   either of you completes adds a star to it, and it appears in both skies with
   both names. Completing it pays both of you a bonus.

Deliberately left out of v1 (keeps it simple): groups/clubs, chat, leaderboards,
Pomodoro-mode together sessions (together = one plain block), video/audio,
shared constellations with more than two people, per-item privacy switches.

## Architecture

### Server (new migration per phase; backward compatible per CLAUDE.md)

Friends' data is read **only through security-definer functions that check
friendship**, never by loosening table policies. Why: the sync engine pulls with
RLS alone and no `user_id` filter (`src/shared/sync/supabaseRemote.ts`), so a
friend-read policy would pour friends' rows into your own store; and the
isolation guard's "every policy is owner-only" stays true.

- `profiles (user_id pk → auth.users, display_name text 1–24, friend_code text
  unique, created_at, updated_at, server_updated_at)` — owner select/insert/update;
  code generated server-side.
- `friendships (id uuid pk, requester uuid, addressee uuid, status
  'pending'|'accepted', created_at, responded_at)` — no direct grants; RPCs only.
  Unique on the unordered pair. Removing = delete via RPC.
- RPCs (security definer, `search_path = ''`, `authenticated` only):
  `request_friend(code)`, `respond_friend(id, accept)`, `remove_friend(id)`,
  `my_friends()` (names, codes, status, last focus, streak inputs),
  `friend_sky(friend uuid)` → that friend's ended sessions with their outcome
  (id, seed, started_at, ended_at, actual_focus_s, outcome, star_style — no
  tag_id, no device, no away time; ended-early ones are included because "focus
  this week" counts their focus too),
  constellation choices, sky_theme; refuses unless accepted friends.
- Together (phase 4): `together_rooms (id, host, planned_duration_s, status
  'lobby'|'running'|'cancelled'|'done', starts_at, ends_at, cancelled_by,
  cancelled_at)`, `together_members (room_id, user_id, joined_at)`; RPCs
  `create_room`, `join_room`, `start_room`, `cancel_room`. `sessions.together_id
  uuid null` (nullable → older apps unaffected). Live updates via Supabase
  Realtime on `together_rooms` rows the member belongs to. ("Focusing now"
  turned out not to need Realtime: phase 3 uses `focus_status`, polled.)
- Shared constellations (phase 5): `shared_constellations (id, a, b, shape_id,
  seed, tier, proposed_by, status 'proposed'|'active', created_at, accepted_at)`;
  progress is **derived**, never stored, from both members' completed sessions
  after `accepted_at` (fetched with `friend_sky`).

### Client

- New slice `src/features/friends/` (`domain/`, `data/`, `hooks/`, `ui/`,
  `index.ts`); opaque to other slices as `eslint.config.js` enforces; wired in
  `src/app/routes/HomeRoute.tsx` (new `'friends'` view + pill).
- **Reuse, don't rebuild:**
  - Friend's sky: `wire.ts` row decoders → `toCompleted`/`toChoice`
    (`features/sky/data/skyRepository.ts`, export them) → `deriveSky`
    (`features/sky/domain/derive.ts`) with `tierRules(false)` →
    `ConstellationLayer` (prop-only). `SkyBackdrop`/`AmbientCanvas` gain an
    optional `sky` + `themeKey` prop instead of always reading Dexie.
  - Summary stats: `totals` (`features/stats/domain/aggregate.ts`), `streakAt`
    (`features/progression/domain/streak.ts`).
  - Shared constellation picker: `ConstellationPicker` / catalogue, without the
    `chooseConstellation` write.
  - Together timer: the existing machine in `features/timer/domain/timerMachine.ts`
    — a together session is an ordinary session with `togetherId`, fixed
    `startedAt`/end from the room; a remote cancel sends the machine's existing
    cancel path. Desktop deadline via `CompletionPort.arm` as now; invites via
    `NotificationPort`.
  - Bonuses: new reconciler kinds in `features/progression/domain/reconcile.ts`,
    keyed as today with the user id first: `together:<roomId>` (paid when every
    member completed) and `shared:<sharedId>` (paid when the derived shared
    constellation completes). Amounts in `domain/economy.ts`.
- Friend data is fetched on open and kept in memory (not Dexie) — it's someone
  else's, and offline the panel says "Connect to see friends".

## Phases (one PR each)

1. **Profiles & friendships (server only):** migration, RPCs, pgTAP (positive
   "friend can read" checks + every existing attack vector against a non-friend
   and a pending friend), isolation guard sets updated deliberately.
2. **Friends panel:** display name + code, add/accept/decline/remove, friend
   list, friend's sky and summary stats.
3. **Focusing now:** a short-lived server status per person (`focus_status`,
   read via `friends_focus()`), polled every 15 s while Friends is open.
4. **Focus together:** rooms, lobby, synchronized start, everyone-fails cancel,
   together bonus, desktop invite notification, the CLAUDE.md decision.
5. **Shared constellations:** propose/accept, derived progress in both skies,
   completion bonus.

Each phase can ship in its own release; 1–3 are useful alone.

## Outcomes → acceptance tests

1. **Only friends see anything, and only what was agreed.**
   1.1 pgTAP: user C (not a friend) calling `friend_sky(A)` is refused; same for a
   *pending* request; after `remove_friend`, refused again.
   1.2 pgTAP: B (accepted friend) gets A's ended sessions (with outcome) and
   choices; the result has no `tag_id`, `device` or `away_ms`.
   1.3 pgTAP: no new policy on existing tables; isolation fingerprint of A's rows
   unchanged after B's and C's attacks; anon can call none of the RPCs.
   1.4 e2e: after a normal sync on B's device, B's local store contains zero of
   A's rows.
2. **Making a friend is three steps.**
   2.1 e2e web: A copies their code, B enters it, A accepts → both lists show each
   other by display name. Wrong code → "No one has that code"; own code and
   duplicate request refused with a clear message.
3. **A friend's sky is their sky.**
   3.1 unit: `deriveSky` on decoded `friend_sky` rows equals A's own `deriveSky`
   (same stars, constellations, theme).
   3.2 e2e: B opens A's page → A's constellations drawn, summary numbers equal A's
   own Stats for the week (focus, stars, streak).
4. **Focusing now is visible.** (Phase 3, decided 2026-10-23: no live channel;
   the app sets a server status on each change and an open Friends panel
   re-checks every 15 s. Pomodoro breaks show "On a break".)
   4.1 e2e two devices: A starts a session → within ~20 s B's list shows "Focusing
   now · N min left"; A ends → it clears; a Pomodoro break shows "On a break".
5. **Together: same end time, and a cancel fails everyone.**
   5.1 e2e: A invites B, B joins, A starts → both timers show the same end time
   (±1 s); both complete → both get a star and the together bonus once
   (ledger id `together:<room>`), across repeated reconciles.
   5.2 e2e: B cancels mid-way → A's session ends early within ~5 s with
   "B ended the session"; neither gets a star or the bonus.
   5.3 e2e: A goes offline (route blocked), B cancels, A reconnects before the end
   → A's session ends as cancelled at B's cancel time.
   5.4 A's tab hidden / app minimised the whole time → still completes (leaving
   never forfeits).
   5.5 desktop: the invite raises a Windows notification (via `debug_native_log`).
6. **Shared constellation fills from either friend.**
   6.1 unit: derived progress takes both members' qualifying sessions after
   `accepted_at`, in end order, respecting tier minimums.
   6.2 e2e: A and B each complete sessions → it appears in both skies with both
   names and the same progress; completing it pays each one bonus once.
7. **Nothing breaks for people who don't update.**
   7.1 A 0.2.1 build syncs against the new schema: sessions with and without
   `together_id` upload and pull; CI's existing suites stay green.

## Verification per phase

`npm run lint`, `npm test`, `npx supabase test db`, `npm run e2e:web` (local
stack), `npm run e2e:desktop` for phases 4–5, then a `qa-lead` pass before each
release. Each case above reported with its observed result.

## Model recommendation

Multi-file architecture across server security, sync boundaries, the timer
machine and the reconciler, with real-time coordination edge cases (phase 4).
**Stay on the stronger-reasoning model (Opus)** for phases 1, 4 and 5; phases 2
and 3 are straightforward UI building and suit the faster model (Sonnet).
