# M1 — The timer

## Context

M0 and M0.5 shipped an installable shell: a Tauri desktop app with a browser
build alongside it, a local IndexedDB store, and a runtime capability layer
(`src/shared/runtime/`) that hides which host the app is running in. There is
no timer yet. M1 adds it: pick a duration, commit to it, and have the session
recorded accurately — plus the desktop surfaces that only make sense once a
timer exists (tray countdown, mini-window contents, completion notification).

This plan reconstructs the M1 design agreed on 2026-08-31, before the Tauri
pivot overwrote the working plan file, and updates it for the desktop target.
Read `CLAUDE.md` → *Decisions already made* first; several of them are load-
bearing here and are not re-argued below.

### Settled before this plan (do not re-open)

| Question | Decision |
|---|---|
| Leaving the app | Never forfeits. The timer runs on wall-clock time regardless of window state, minimise, close-to-tray, or a quit. |
| How a session fails | Only by an explicit cancel, behind a confirmation. |
| Grace period / wake lock / policy split / `abandoned` outcome | All removed in M0.5. Do not reintroduce. |
| Time spent away | Recorded in `SessionRow.awayMs` as a stat only. Never affects success. |
| Session modes | Countdown only. Pomodoro is M3. |
| Elapsed time | Always `now - startedAt`, never accumulated from ticks. |

### Decided in this plan (reopen in review if you disagree)

| Question | Decision | Why |
|---|---|---|
| Who owns the deadline on desktop | **Rust**, not the webview | WebView2 throttles timers in hidden or minimised windows, which is exactly when a completion notice matters. A Rust thread is not throttled. |
| Tray countdown on Windows | **Tooltip only**, minute granularity | Rendering minutes into the icon image is possible with the procedural PNG generator but is polish, not core. Revisit after M2. |
| Mini window contents | **Read-only**: remaining time and a thin progress bar | Cancelling is a deliberate act and belongs behind the main window's confirmation, not on a 240px floating panel. |
| Durations | Presets **25 / 50 / 90** plus a custom value, **5–180 min** in 5-min steps | Presets cover the common case in one click; custom stops the app feeling rigid. |
| Very short test sessions | A **1-minute preset in dev builds only** (`import.meta.env.DEV`) | Acceptance tests need sessions that finish in minutes, not half an hour. Never ships. |

## The core idea, in one function

Background continuation reduces to this, called once on app start and again
whenever the window becomes visible:

```ts
// src/features/timer/domain/resume.ts
export type ResumeVerdict =
  | { kind: 'running'; remainingMs: number }
  | { kind: 'completed'; endedAt: number; actualFocusS: number };

export const resumeVerdict = (session: ActiveSession, now: number): ResumeVerdict;
```

**The detail that matters:** when a session finished while the app was hidden
or quit, `endedAt` is `plannedEndAt(session)`, **not** `now`. A session ended
when it ended, not when you got around to noticing. Getting this wrong
silently corrupts every future stat and streak in M4 and M6.

### Domain contracts

```ts
// domain/types.ts
export interface ActiveSession {
  id: string;
  startedAt: number;        // epoch ms
  plannedDurationS: number;
  seed: string;
  tagId: string | null;
  device: string;
  awayMs: number;
}
export interface SessionDraft { plannedDurationS: number; tagId: string | null }
export interface SessionEnding {
  outcome: 'completed' | 'cancelled';
  endedAt: number;
  actualFocusS: number;
}

// domain/session.ts — pure; `now` is always injected, never read
export const elapsedMs    = (s: ActiveSession, now: number): number; // clamped >= 0
export const remainingMs  = (s: ActiveSession, now: number): number; // clamped >= 0
export const plannedEndAt = (s: ActiveSession): number;
export const isComplete   = (s: ActiveSession, now: number): boolean;
```

`actualFocusS` for a cancel is `floor(elapsedMs / 1000)`, capped at the
planned duration. For a completion it is exactly `plannedDurationS`.

### Repository contracts

```ts
// data/sessionRepository.ts
export const startSession      = (db: WorkTimerDb, draft: SessionDraft, ctx: StartContext): Promise<ActiveSession>;
export const loadActiveSession = (db: WorkTimerDb): Promise<ActiveSession | undefined>;
export const finishSession     = (db: WorkTimerDb, id: string, end: SessionEnding): Promise<void>;
export const addAwayTime       = (db: WorkTimerDb, id: string, deltaMs: number): Promise<void>;
```

- `startSession` writes the row and `META_KEYS.activeSessionId` **in one Dexie
  transaction**. It rejects if a session is already active rather than
  silently starting a second one.
- `finishSession` writes the final fields and clears `activeSessionId` in one
  transaction. It is **idempotent**: finishing an already-finished session is a
  no-op, which is what makes "reload twice after completing while away" safe.
- `loadActiveSession` treats a dangling `activeSessionId` (pointer to a missing
  row) as no active session and clears the pointer.

Reuse — all of these exist from M0/M0.5: `readMeta` / `writeMeta` /
`clearMeta`, `META_KEYS.activeSessionId` (`src/shared/db/meta.ts`), `newId` /
`newSeed` (`src/shared/lib/id.ts`), `systemClock` / `createTestClock`
(`src/shared/lib/clock.ts`), `getRuntime` / `describeHost`
(`src/shared/runtime/index.ts`).

**No schema change.** `SessionRow` already has every field M1 needs, so
`db.version(1)` stays as shipped.

### State machine

Three states: `idle`, `running`, `finished`. It holds no timing logic — it
delegates every time question to `domain/session.ts` with an injected clock.

| From | Event | To | Effect |
|---|---|---|---|
| `idle` | `START(draft)` | `running` | `startSession`, `completion.arm` |
| `idle` | `RESUME(session)` | `running` or `finished` | via `resumeVerdict` |
| `running` | `TICK_DUE` | `finished` | `finishSession(completed)` with `endedAt = plannedEndAt` |
| `running` | `CANCEL_CONFIRMED` | `finished` | `finishSession(cancelled)`, `completion.disarm` |
| `finished` | `DISMISS` | `idle` | clears the result screen |

XState rather than a reducer because M3's Pomodoro cycling is genuinely
machine-shaped; extending three states beats rewriting a reducer.

### The new runtime port

The existing `NotificationPort` and `TrayPort` stay. M1 adds one port that
owns "this session ends at T":

```ts
// shared/runtime/types.ts
export interface CompletionPort {
  isSupported: boolean;
  /** Tell the host a session ends at `endsAt`. Replaces any previous arm. */
  arm(o: { sessionId: string; endsAt: number; title: string; body: string }): Promise<void>;
  /** Forget the deadline: no notice, tray back to plain name. Idempotent. */
  disarm(sessionId: string): Promise<void>;
}
```

- **Desktop:** `arm` invokes the Rust command `arm_deadline`. A thread sleeps
  to each minute boundary, updates the tray tooltip (`Starkeep — 24 min left`),
  and at `endsAt` fires the OS notification and resets the tooltip. `disarm`
  invokes `disarm_deadline`. One deadline at a time, held in a
  `Mutex<Option<Deadline>>` managed state.
- **Web:** `setTimeout` to `endsAt` plus the Notification API. Best-effort —
  background tabs throttle timers to about once a minute.
- **Unsupported** is the usual silent no-op.

The JS side still runs `resumeVerdict` on start and on visibility. That covers
the one case Rust cannot: the whole app was **quit**, so no process existed at
the deadline. In that case there is no OS notice; the main window opens on the
result screen stating the real end time ("Finished at 3:40 pm").

### Mini window

Reads the active session through `useActiveSession` (a Dexie `liveQuery`),
computes remaining time from the clock itself, and shows mm:ss plus a thin
progress bar. With no active session it shows `--:--`. It never writes to the
database. The main window gains a "Pop out" button that calls
`runtime.miniWindow.open()`.

### Repaint loop

`useTick` re-renders about 4×/second while a session is running *and* the
document is visible, and stops when hidden. Every displayed number is derived
from `clock.now()` at render time.

## Outcomes and acceptance tests

**O1 — Elapsed time is correct across hiding, closing, and reloading.**
1. Start a 25-minute session, reload the window at about 1 minute. *Pass:*
   resumes showing about 24 minutes left, not a fresh 25.
2. Start the 1-minute dev session, quit from the tray, relaunch after 2
   minutes. *Pass:* recorded `completed`, `endedAt` equal to start + 60s, and
   the window opens on the result screen showing that end time.
3. Unit: with `createTestClock`, `elapsedMs` equals the wall-clock delta
   regardless of how many ticks fired.
4. Unit: clock moved backwards. *Pass:* `elapsedMs` clamps to 0; no negative
   remaining time, no throw.

**O2 — The only way to fail is to cancel.**
5. Start a session, minimise to tray for 2 minutes, restore. *Pass:* still
   running, countdown correct, nothing forfeited.
6. Cancel and confirm. *Pass:* recorded `cancelled`, `actualFocusS` equals
   elapsed seconds, `activeSessionId` cleared, tray back to "Starkeep".
7. Open the cancel dialog and dismiss it. *Pass:* session untouched.

**O3 — Completion is recorded accurately and exactly once.**
8. Let a session finish with the window open. *Pass:* `completed`,
   `actualFocusS` equals the planned duration.
9. After a session completes while hidden, reload twice. *Pass:* exactly one
   completed row; no duplicate; `activeSessionId` cleared.
10. Unit: `finishSession` called twice on the same id. *Pass:* second call is a
    no-op; the row is unchanged.
11. Unit: `startSession` while one is active. *Pass:* rejects; no second row.

**O4 — Desktop surfaces track the session.**
12. Start a session, close to tray, hover the tray icon. *Pass:* tooltip reads
    the minutes remaining and updates as minutes pass.
13. Start the 1-minute dev session, minimise to tray, switch to another app.
    *Pass:* the OS notification appears within a few seconds of the deadline,
    not a minute late.
14. Open the mini window during a session. *Pass:* shows the same remaining
    time as the main window, stays above other windows, and shows `--:--` after
    the session ends.

**O5 — The browser build degrades rather than breaks.**
15. Run a 1-minute dev session in the browser build. *Pass:* records correctly;
    notification fires if permitted; tray and mini-window controls are hidden;
    no console errors.
16. Deny notification permission. *Pass:* the timer works normally; no repeated
    prompting.

**O6 — Away time is recorded but never punitive.**
17. Hide the window for about 30 seconds during a session, then let it finish.
    *Pass:* `awayMs` is roughly 30000 and the outcome is still `completed`.

## Known limits

- **A fully quit app sends no completion notice.** No process exists at the
  deadline. The result screen on next launch is the fallback. A Windows
  scheduled toast could cover this but is out of scope.
- **Device clock changes are not defended against.** Moving the clock forward
  completes a session early. Honour-system app; server-side sanity checks are
  an M5 concern.
- **Tray text is hover-only on Windows.** Accepted for M1 (see decisions).

## Model recommendation

**Stay on the stronger-reasoning model.** This milestone spans two languages
and a cross-process deadline, and its hard parts are subtle correctness —
`endedAt` on resume, idempotent finishing, the Rust/JS split for who fires the
notice. The UI components alone would suit a faster model, but not enough to
be worth splitting the milestone.
